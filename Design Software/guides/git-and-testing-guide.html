Git Version Control & Testing Guide

Learn how to save project checkpoints with Git in VS Code, undo mistakes, review changes, and test your ordering system.

👋 Read This Before You Start Coding!
Set up Git before editing your code so you can save safe checkpoints at each stage of your project. If something ever breaks, Git lets you jump back to an earlier working version with one click!

🤔 What is Git and Why is it Useful?

Think of Git like a magical video game save system for your code and project files.

  • 🎮 Save Points (Commits): Instead of saving messy files like app_final_v2_reallyfinal.js, Git lets you save clean milestone checkpoints (e.g. "Added 10 menu items").
  • ⏪ Time Machine / Undo Safety Net: If you edit some code that accidentally breaks your app, Git allows you to instantly roll back to your last working checkpoint with no stress.
  • 🔍 Compare Differences: You can see a side-by-side view showing exactly what lines of code you added, changed, or deleted.

📥 1. Cloning Your Project Repository from GitHub

Your teacher will provide the GitHub repository link for the canteen starter project. Cloning copies the entire project folder and all its version history directly onto your computer.

Step 1: Clone the Repo in VS Code (Choose One Method)

Method A (Using VS Code Interface):

  1. Open VS Code.
  2. On the Welcome page, click "Clone Git Repository..." (or press Ctrl + Shift + P and type "Git: Clone").
  3. Paste the repository URL provided by your teacher and press Enter.
  4. Choose a folder on your student drive to save it, then click "Open Repository" when prompted.

Method B (Using Terminal):

git clone <REPOSITORY-URL>

Once opened, all starter files, templates, and example folders will be ready in your workspace!

⚠️ Important Note on Project Booklets:
Do NOT save or move your booklet.docx (Word document) into your Git repository folder. OneDrive syncing and Word file locks can interfere with Git tracking. Keep your Word booklet stored in your student coursework folder outside the repository.

⚙️ 2. One-Time Git Identity Setup (Per-Project Local Config)

Because college computers are shared between different students and accounts, configure Git for your project workspace (using local config, not global):

Step 2: Set Your Student Identity in the Terminal

Click Terminal → New Terminal (or press Ctrl + `), then type these two commands (press Enter after each):

git config user.name "Your Full Name"
git config user.email "your.student.email@college.ac.uk"

Note: We do not use --global here so your personal details stay tied strictly to your own project folder.

💾 3. How to Save a Checkpoint (Commit All Changes)

A commit is a permanent snapshot of all your project files. You don't need to manually stage individual files — you can commit all your edits in one simple action:

Step 3: Committing in the VS Code GUI
  1. Click the Source Control icon on the left activity bar (or press Ctrl + Shift + G).
  2. In the Message box at the top, type a short message describing what you just completed (e.g. "style: changed theme to retro diner").
  3. Click the blue Commit button (or press Ctrl + Enter).
  4. If VS Code asks: "There are no staged changes to commit. Would you like to stage all your changes and commit them directly?", click Always.
Clear Commit Message Examples:
  • "feat: added 10 researched food items and local images"
  • "style: customized layout to sidebar-left and punk theme"
  • "feat: completed subtotal calculation and budget check"
  • "fix: corrected allergen warning text for dairy products"

🧪 4. Practice Activity: Change Theme, Commit & Review Changes

Try this quick test right now to see Git's version control powers in action:

🎯 Step-by-Step Git Test:
  1. Open index.html and change your <body> class (for example, change theme-modern to theme-retro). Save the file (Ctrl + S).
  2. Open the Source Control panel (Ctrl + Shift + G). Notice index.html is listed under Changes with an M (Modified).
  3. Click on index.html in the list. VS Code opens a side-by-side Diff View comparing the old code (red on the left) with your new code (green on the right)!
  4. In the commit message box, type: "test: updated theme to retro" and click Commit.
  5. Notice that the Changes list is now completely clean — your checkpoint is safely saved!

⏪ 5. How to Roll Back / Revert Mistakes

If you make an edit that breaks your app, or you want to undo changes since your last commit:

Option A: Discard Unsaved Changes (Clean Slate)

If you made changes in a file that you haven't committed yet and want to throw them away:

  • In the Source Control panel, hover over the modified file under Changes.
  • Click the Discard Changes icon (the curved back-arrow ⤺).
  • VS Code will instantly restore the file back to your last saved commit!
Option B: View History or Checkout an Earlier Commit

To view your timeline of saved checkpoints or restore an earlier version:

  • In the Source Control panel, look at the Timeline or Graph / Commits section at the bottom left.
  • Click on any previous commit to view exactly what was changed at that moment.
  • If you need to restore your whole project to an earlier commit in the terminal, you can run: 
    git checkout HEAD~1 .
    (This restores all files to the previous commit while keeping you safe).
